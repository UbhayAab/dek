## 2. Decisions

1. **Scope.** Only Jarurat Care (019f993c-604d-...-e406dd9da295) and Safalta Setu (019f993c-6130-...-bc9424bb0248) are copied, with their legacy ids (legacy_id = id). The other 49 organizations are test fixtures and stay in the legacy project, which remains the archive.
2. **Scope.** Users: every member of either real org, plus accounts in no org whose email domain is not a test domain (hearth.test, dek.app, dek-backend.test, apps.invalid). The app identity and accounts that belong only to synthetic orgs are excluded [5 such accounts: 4 in a testorg_* fixture, 1 in Hearth Demo].
3. **Identity.** auth.users and auth.identities are copied with the same ids, password hashes (bcrypt; passwords keep working), email confirmation, created_at, last_sign_in_at and metadata. Pending one-time tokens (password reset, confirmation) are blanked: their links point at the legacy project. Pending email changes are cancelled.
4. **Identity.** auth.sessions not expired and holding a non-revoked refresh token are copied with their non-revoked refresh tokens and AMR claims, so the new client can exchange the refresh token it already holds for a new session without a sign-in (proved with a throwaway user by --prove-auth). Refresh token row ids come from the new sequence; the token string is the key.
5. **Identity.** Profiles: display_name, handle = lowercased legacy username when it fits ^[a-z0-9][a-z0-9._-]{1,30}$ (else null), title, timezone, status, last_active_at = last_sign_in_at, avatar copied from the legacy attachments bucket to the public avatars bucket at <user id>/<file name>. Pronouns, bio, phone, department, location, start date and manager are not in the new profile and go to the archive.
6. **Identity.** Notification preferences: legacy quiet hours (whole hours, e.g. 23 to 7) become quiet_start/quiet_end HH:00 in the person's timezone. digest and dnd_until are not carried (no migrated user has an active dnd).
7. **Identity.** Platform admins: the legacy platform admins who are migrated users. All 9 legacy platform admins are hearth.test fixtures, so none are migrated.
8. **Roles.** Org roles: admin -> admin, member -> member. Owner: in each org, Ubhay's account that is a member of that org (the primary address first, else the secondary) [Safalta Setu: the primary account, an admin there; Jarurat Care: the primary account is not a member, so the secondary account, a member there]. Matched by sha256 of the address; no address is stored in the repository.
9. **Roles.** Org created_by: legacy organizations have no creator column; the creator of the org's first workspace, created in the same instant as the org, is recorded.
10. **Roles.** Server roles (LEGACY-MAP section 7): the workspace creator or a holder of a role with ADMINISTRATOR (1<<40) -> admin; member_type moderator, or a holder of a role with MANAGE_MESSAGES (1<<1) -> moderator; otherwise member. MANAGE_MESSAGES covers the Moderator role (2007) and the lead roles HR Lead, PM, Pod Lead and Team Lead (1942 = manage messages, channels, kick, invite, mention everyone, timeout, threads), which moderated in all but name. Org admins are server admins through the access helpers.
11. **Servers.** Workspaces -> servers with the same ids. position by created_at within the org. join_policy: requires_approval -> approval, else open or invite as in legacy. Archived servers stay archived (Carcinome; a pending scheduled deletion also counts as archived). rules_text becomes the description. Names are unique per org among unarchived servers (no rename was needed).
12. **Channels.** Channels keep their ids. text, announcement and forum -> text; voice -> audio. announcement or readonly -> posting_policy admins. is_private -> visibility. Category name kept. position = order of the legacy position. Archived state kept. The channel the legacy client opened on arrival (default_channel_id, else #general, else the first non-voice channel) gets auto_join. Names unique per server among unarchived channels, case-insensitive, with a -2 suffix if needed (none needed).
13. **Channels.** Membership: legacy showed every public channel to every workspace member, so every server member becomes a member of every public channel of that server. Private channels keep their legacy channel_members. Legacy create_channel added only the creator to a new private channel, so a private channel with exactly one member records that member as created_by and channel owner.
14. **DMs.** Conversations -> channels of kind dm with the conversation id, org = the workspace's org, dm_key = <org>:<the two user ids sorted>. A pair with two conversations in one org (2 pairs) merges into the older conversation; the other id is recorded in dek_migration.id_map. Conversations without members are skipped.
15. **Messages.** Channel and DM messages keep their ids (legacy_id set). seq is renumbered per channel from 1 in (legacy seq, created_at) order; a merged DM is ordered by created_at. channel_state.last_seq, last_top_seq and last_message_at are recomputed. meta.legacy.seq keeps the old number for old #/m/<channel>/<seq> links.
16. **Messages.** Threads: replies get thread_root_id = the root message; roots stay top level; a thread whose replies were never written is an ordinary message. also_send_to_channel -> also_in_channel (in_timeline follows the table check). reply_count counts live replies; last_reply_at and reply_user_ids include every reply, as sending would have.
17. **Messages.** Bodies: body_text is canonical. Form, poll and event cards become readable text ("Form: <title> (form retired)"). A legacy reply_to_id (channel and DM; the legacy client rendered a quote for both) becomes a leading "> Name: first 90 characters" line, and meta.legacy.reply_to keeps the quoted message id.
18. **Messages.** Mentions: @username and @Display Name text becomes <@uuid> by longest match, using the legacy client's word edges, only for ids in mention_user_ids that are migrated users; unmatched text stays. mentions = the mention_user_ids who can read the channel. mention_scope here/channel -> mention_all and the text @here/@channel -> <!here>/<!channel>. dek.mentions rows carry the new seq (the author is not mentioned to themself).
19. **Messages.** client_id = client_msg_id; edited_at and deleted_at kept. A deleted message is the new tombstone: empty body, no mentions, reactions, saves, pins or attachments.
20. **Messages.** Reactions and DM reactions -> dek.reactions plus the messages.reactions summary {emoji: [user ids by reaction time]}. Pins -> pinned_at/pinned_by (none in the real orgs).
21. **Files.** Each element of a message's attachments json becomes a dek.attachments row (status ready, message_id set, uploader = the message author). The first reference to a stored file keeps the legacy attachment id; later references and elements without a legacy row get uuid v5 ids (id map). Bytes are copied from the private legacy bucket to media/<org>/<channel>/<attachment>/<safe file name>; a thumbnail goes to thumb.<its extension> (thumb.webp only when it is webp). Every copy is read back and must match size and sha256; declared_mime keeps the legacy value (e.g. audio/webm;codecs=opus), mime_type the base type.
22. **Read state.** Valid read_state rows only (the user is a member of an existing channel). last_read_seq is mapped through the old-to-new seq map: the highest new seq whose legacy seq is at or below the legacy cursor, so exactly the same messages are unread. notify_level inherit/all/mentions/nothing -> default/all/mentions/none. Members without a legacy cursor start at 0, as in legacy.
23. **Read state.** DM cursors come from conversation_members.last_read_seq; for a merged DM the cursor is the largest prefix of the merged history read in both conversations. thread_followers -> thread_follows (following = true); thread read cursors -> last_read_reply_seq (following = false unless the person also followed).
24. **Saved.** saved_items -> saved_messages. The legacy Later-board state (todo/done) and reminders are not part of a bookmark; they are kept in the archive.
25. **Invites.** Workspace invites and org invites -> dek.invites with code = null and code_sha256 = the legacy token hash. The live legacy functions hash with extensions.digest(token, 'sha256') on a UTF8 database, which equals sha256(convert_to(token, 'UTF8')) (checked live), so old links keep working. Server invites carry server_id; org invites have none. role member (the one admin-granting org invite becomes member; workspace role grants are not representable and none exist). requires_approval false (legacy redemption skipped approval). No expiry -> 2100-01-01. use_count = uses.
26. **Membership.** Workspace join requests -> dek.join_requests (status kept). The one workspace ban becomes an audit note in its org (action legacy.server_ban): the new model has no server bans.
27. **Devices.** push_subscriptions -> push_devices kind webpush, enabled = false, label = browser and OS from the user agent, platform; one device per endpoint. Turning them on is --enable-push, run by the lead at cutover. Nothing in this migration sends a notification: no intents are written (checked, and the load rolls back if any appear).
28. **Archive.** Off-scope data of the real orgs (tasks, polls, events, forms, canvases, away days, leave policies, workspace roles and role holders, scheduled messages) and of migrated users (drafts, nicknames, saved-item states, extra profile fields) is exported as JSON to Desktop/claude/dek-legacy-archive/_archive_2026-10-03 and not loaded. It is outside every repository on purpose: the brief named dek-legacy/_archive_2026-10-03, but the legacy deploy publishes every top-level folder of dek-legacy that git does not ignore, so that folder would have gone live with personal data.
29. **Process.** Re-runnable: every write is an upsert that changes a row only when a value differs; what the migration wrote is listed in dek_migration.owned so a row that disappears from legacy (someone left, a token was revoked) is removed at the next run and app-created rows are never touched. One transaction for all database writes. A full run refuses once the new app is in use (dek.settings.migrations_frozen; app messages or DMs in migrated channels; refresh tokens, reactions or saves the new project made for migrated people), because it would overwrite their new changes. After go-live the straggler pass is --apply --sessions-only: insert-only for accounts, sessions and refresh tokens legacy created since the final pass (legacy auth keeps rotating tokens after the legacy API is frozen), never reviving a session or account the new app ended. Copied refresh tokens are insert-only, so a token the new project rotated is never made usable again.

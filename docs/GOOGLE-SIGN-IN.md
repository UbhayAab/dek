# Google sign-in - issue 117

Google is an additional identity sign-in for existing approved accounts. Supabase keeps signup disabled and remains authoritative for identity linking. Existing API membership, disabled-user, invitation and role checks are unchanged. Password and email-code recovery remain available. DEK requests only openid, email and profile. Gmail read/send grants are not part of this feature.

The browser returns to /auth/google. Native shells use the system Browser plugin and dek://auth/google. The bootstrap removes callback query/hash data before error reporting. A ten-minute single-use intent and SDK PKCE verifier bind the callback to this device/tab; replay, wrong intent, changed account and missing verifier require a new sign-in. Provider credentials never ship in the app. The exchange client only persists verifier keys; its tokens remain in memory until the existing-account guard accepts them into the normal app session.

Release requires the Google provider to be configured for project nxljuctnauhgzekvmftp with an independently reviewed OAuth client, exact Google redirect https://nxljuctnauhgzekvmftp.supabase.co/auth/v1/callback and production origins. Add https://dek-7o4.pages.dev/auth/google and dek://auth/google to the existing Supabase redirect allowlist without removing other current values or changing disable_signup. Callback intent and SDK flow ID query strings must be supported by the allowlist. Do not store client secrets in source or evidence.

Native: npm ci in apps/mobile, run the normal web build and cap sync, and rebuild/sign the existing Android/iOS shells through docs/NATIVE.md. Older installed builds keep password/email-code sign-in and show the update explanation for Google. Unit tests and a compiled shell do not prove a physical phone sign-in. Verify cold/warm return, browser cancellation, account choice, backgrounding and logout on a real device. Preserve unrelated app/store signing configuration.

Before closing 117, verify a real consent flow using an already approved account: unchanged UID, organisations and role, reload/refresh session, password/code fallback and shared-device logout. Confirm a new unapproved account is rejected. A code-only preview or Google test-user configuration is not public readiness. No mail sends, schema/RPC/grant changes or production membership fixtures are needed for this feature.

Configuration on 29 October 2026: a separate DEK staff sign-in OAuth client is configured in the existing organisation Google Cloud project. Its secret is held in the protected local DEK secret store and Supabase Auth, never in this repository. Google is enabled for the active DEK project, signup remains disabled, existing callback entries are retained and all other Auth fields were verified unchanged. The native query callback pattern is `dek://auth/google\?intent=*`; the SDK flow ID is bound to the pending intent. Physical device and real existing-account verification are still separate release checks.
